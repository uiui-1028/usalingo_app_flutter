# 決定｜英単語のテキストをAIで作り、受け取り用シートへ送る

決定日: 2026-09-30

## 決めること

[教材の正本と単語リスト](content-source-and-word-list-20260907.md) は、AIによるテキスト生成を
「2つ目のコンセプトを足すとき、または1000語を超えるときに設計する」とした。いま、その両方が来た。

- 本番にある大学受験1000語は、**まだテストデータ**である
- シリーズごとに単語を増やし、合計およそ3000語（目安。増減してよい）にしたい
- 2つ目のコンセプトの例文を作りたい

画像は今回作らない。テキストを先に作る。

## 選択肢

| 論点 | 選択肢 |
|---|---|
| 生成の手段 | A. クラウドセッションの中でAIが作る / B. Claude APIを呼ぶスクリプトで作る |
| データの置き場所 | A. 公開リポジトリ / B. リポジトリの外（Sheetsなど） |
| 送り先 | A. 原本 `usgs_master_v5` へ直接 / B. 別の受け取り用シート |
| 送り方 | A. AIが1マスずつ書く / B. AIがファイルを作り、スクリプトがまとめて送る |
| 今の1000語 | A. 残して1001から足す / B. 捨てて作り直す / C. 新しい基準で作り直してそろえる |

## 決めたこと

| 項目 | 決定 |
|---|---|
| 目的 | 1000語を超える単語の追加と、2つ目のコンセプトの例文生成 |
| シリーズ | **受験**（中学・高校・大学）と **TOEIC**（600点・730点・860点・990点）の2種類 |
| シリーズ内の分け方 | 受験は段階が**重ならない**ように分ける。TOEICは点数ごとに分ける |
| 語数 | 合計およそ3000語。目安であり、シリーズごとに必要な数で増減する |
| 単語リストの作り方 | 無料の単語リストと有名な単語帳の**見出し語**を足し合わせ、頻度・CEFR・載っている冊数で点数を付けて振り分ける |
| 並び順 | 別に決める（単語リストを作る課題の中で、決定記録を残す） |
| 意味の指定と重複 | 先に意味（sense）まで指定する。単語と意味は全体で1回だけ作り、シリーズのデッキ（`04_deck_words`）は同じ `sense_id` を指す |
| 意味の数 | 上限を決めない |
| 今の1000語 | **C**。新しい単語リストに含め、同じ基準で作り直す |
| 作る列 | 必須の列を先に作り、任意の列はあとで作る |
| 2つ目のコンセプト | 二次元。`concept_code` は `anime` |
| 生成の手段 | **A**。クラウドセッションの中でAIが作る。APIは従量課金で別の請求になるため使わない |
| データの置き場所 | **B**。リポジトリにはスクリプトとルールだけを置き、生成データは置かない |
| 送り先 | **B**。原本とは別の、非公開の受け取り用シート |
| 送り方 | **B**。AIがファイルを作り、スクリプトがGoogleのサービスアカウントでまとめて送る |
| 原本への取りこみ | 人が受け取り用シートから原本へ移す |
| 検査 | **生成データの検査スクリプトを作る** |
| 正しさの確認 | 人が抜き取りで確認する。割合は仮に1割 |

## 理由

**リポジトリが公開だから、データを置かない。** 教材はUsalingoのいちばんの強みで、公開リポジトリに
置くと誰でも持ち出せる。クラウドセッションのファイルは終わると消えるため、受け取り用シートが
消えない置き場を兼ねる。

**1マスずつ書かない。** AIがセルを1つずつ書くと、AIの利用枠を大量に使う。AIはファイルを作るだけにし、
送るのはスクリプトに任せれば、送る作業では利用枠をほぼ使わない。

**原本へ直接送らない。** AIの誤りが原本に入らない。鍵に渡す権限も、受け取り用シートの編集だけで済む。
原本は「リンクを知っている人は閲覧可」のため、確認前のデータを置く場所にも向かない。

**検査スクリプトを作る。** 2026-09-07の決定は、在るデータを流すだけだったのでDBの制約を門番にした。
AIが数千行を作るときは、投入の前に形の誤りを見つけたい。見本の誤りは全件に写るので、早く止める。

**意味を先に指定する。** シリーズの間で同じ単語が出る。単語や意味を2回作ると、直すときに片方だけ
直る。V5はデッキが `sense_id` を指す作りなので、意味を1回だけ作れば重複は起きない。

## 守ること

- 単語帳から使うのは**見出し語だけ**にする。意味・例文・並び順を写さない
- 単語帳から集めた生のリストは、公開リポジトリに置かない
- 無料のリスト（NGSLなど）は、使う前にライセンスと表示の条件を確かめる
- 鍵（サービスアカウントのJSON）は、環境のシークレット `GOOGLE_SERVICE_ACCOUNT_JSON` に置く。
  チャット、リポジトリ、Notionに書かない
- 本番Supabaseへの反映は、これまでどおり [同期の手順](../operations/sync-sheet-to-supabase.md) で行い、実行前に承認を得る

## この決定で変わる、前の決定

[教材の正本と単語リスト](content-source-and-word-list-20260907.md) の次の行は、この決定で置き換える。
正本をSpreadsheetにすること、同期を片方向にすること、Supabaseを生成に関与させないことは変えない。

| 前の決定 | 今回 |
|---|---|
| 単語リストは大学受験頻出順で1000語 | 受験とTOEICの2シリーズ、合計およそ3000語 |
| コンセプトは `simple` 1種のみ | `simple` と `anime` |
| AIによるテキスト生成と校正ループは今回は作らない | 作る |
| 投入前の検査スクリプトは作らない | 生成データの検査スクリプトを作る |

## 影響する場所

- [`docs/content/source-database-v5.md`](../content/source-database-v5.md): 列の決まりは変えない。生成データはこの決まりに合わせる
- `02_content_concepts`: `anime` の行を足す
- `04_decks`・`04_deck_words`: シリーズと段階ごとのデッキを足す
- 新しいスクリプト: 生成データの検査、受け取り用シートへの送信

## 見直す条件

- 20語で試した結果、1割の抜き取りで誤りが多い
- クラウドセッションの利用枠が、生成に足りない
- 教材を非公開にする方針が変わる
