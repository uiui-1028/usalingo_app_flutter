# 公式デッキを「箱」で配る 要件と引き継ぎ

利用者と合意した要件の正本。作業1（箱）の要件は確定し（2026-10-08）、実装した。本番には migration を当て、シートを書き換えて同期した（2026-10-08）。アプリの公開はまだ。
「未決」に残るのは、シート作業のときに決める文言と、作業2の前に決めることだけ。

## 背景

いまの公式デッキ「大学受験1000語A〜J」（100語×10）は、実は1つの単語リストを10に割ったもので、
まとめて1つの「箱」にあたる。1000語の箱は重いので、500語ずつの2箱（シリーズA・シリーズB）に分け、
利用者には**箱（フォルダ）の単位で選んでもらう**。

同じ単語リストでも、コンセプト（世界観。`simple`・`anime` など）が違えば別の箱として並べる。
ポケモンのブラックとホワイトのように、それぞれが別の選択肢になる。コンセプトを切り替えるボタンは作らない。

## 言葉

| 言葉 | 意味 | 例 |
|---|---|---|
| 箱 | ギャラリーで選ぶ単位。単語リストの一部 × コンセプト1つ。学習タブではフォルダになる | 大学受験 シリーズA（シンプル） |
| デッキ | 箱の中の1回分。いまと同じ100語 | 1〜100 |
| 別版 | 単語リストが同じでコンセプトだけ違う箱どうし | シリーズAのシンプルとアニメ |

## 確定した要件

| # | 項目 | 合意内容 |
|---|---|---|
| X1 | 箱の中身 | 500語の箱に100語のデッキを5つ。いまのA〜EをシリーズA、F〜JをシリーズBに入れる。デッキIDは変えず、学習記録はそのまま残る |
| X2 | 箱の置き場所 | シート（例: `04_deck_boxes`）と Supabase に新しい「箱」の表を作り、デッキは自分の箱を指す。コンセプトとジャンル（大学受験・TOEIC）は箱が持つ |
| X3 | 別版の持ち方 | 両方持てる。学習記録は、**主の意味と出題形式が同じなら共通**にする |
| X4 | 共通の作り方 | カードを共有する。カードを「主の意味 × 出題形式」に1枚だけ作り、デッキは「どのカードを何番目に入れるか」の表で持つ。記録・保留・除外・タグはカードに付いたまま、自然に共通になる |
| X5 | 作る順番 | 箱（表・ギャラリー・フォルダ追加）が先。カードの共有は、重なる箱（アニメ版・TOEIC）を配る前に別の PR で作る。いまの A〜J は単語が重ならず、別版もまだ無いので、先に箱だけ出しても困らない |
| X6 | 学習タブでの見せ方 | ふつうのフォルダ（`LocalDeckFolder`）として入れる。フォルダ名は箱の名前。名前の変更・出し入れ・解散は自由 |
| X7 | 追加済みの判定 | 箱のデッキ5つが全部学習タブにあれば（どのフォルダにあっても）「追加済み」。足りなければ追加でき、足りないデッキだけを入れる |
| X8 | 学習タブにすでにある同じ箱のデッキ | どのフォルダにも入っていないデッキは、新しいフォルダへ移して5つそろえる。利用者が自分でフォルダに入れたデッキは動かさない |
| X9 | 最初から出すもの | いまのまま「大学受験1000語A」1デッキだけ（フォルダにしない）。将来、専用の最初の箱を用意する予定 |
| X10 | 別版の見分け方 | 表紙の絵で見分ける。コンセプト名の表示は戻さない |
| X11 | 表紙の決め方 | 箱の表に「表紙に使う例文」の列を置き、書いてあればその絵を出す。空なら、いまの学習タブと同じく収録単語のイラストから選ぶ（その箱のコンセプトの絵） |
| X12 | すでにA〜Jを個別に追加している利用者 | そのままにする。勝手にフォルダを作らない。ギャラリーから箱を追加すると X7・X8 のとおり足りない分が入る |
| X13 | デッキ名 | シートの `deck_name` を箱に合う名前に付け直す（例: 「1〜100」）。名前の中身は利用者が決める |
| X14 | 詳細シート | 箱（親）とデッキ（子）の両方で数える。上の3項目（収録単語数・容量・レベル）と重なる語数・品詞の内訳は箱全体の値。単語一覧はデッキごとの見出しで区切り、見出しにそのデッキの値を出す |
| X15 | 箱を外す操作 | 新しく作らない。今のフォルダ解散とデッキごとの削除だけ |
| X16 | ダウンロード中のフォルダの枠 | 1デッキのときと同じ（[ギャラリーの要件](deck-gallery-redesign-requirements.md) の T1〜T4）。％は中のデッキの％をならしたもの（終わったデッキは100%）。箱の中のデッキの容量はほぼ同じなので、バイト数で数えるのとほとんど変わらない |
| X17 | ギャラリーの箱の並び順 | シリーズ順。同じシリーズの別版は並べて置く |

## 作りの案（作業1：箱）

| 場所 | 中身 |
|---|---|
| シート | `04_deck_boxes`（`box_id`・`box_name`・`description`・`genre`・`concept_id`・`cover_example_id`・並び順）。`04_decks` に `box_id` を足し、`concept_id` は外す |
| Supabase | `deck_boxes` 表（上の列＋`media_bytes`・`difficulty`）。`decks.box_id` を足す。読み取り権限は `decks` と同じ。`user_added_decks` は今のまま（デッキ単位） |
| 同期スクリプト | 箱を流し、`decks.concept_id` を箱から写す。容量とレベルを箱とデッキの両方で計算する |
| ギャラリー | 箱を並べる。ジャンルは箱の列。追加済みは X7。詳細は X14 |
| 学習タブ | 空き枠から箱を追加すると、足りないデッキを `user_added_decks` に書き、フォルダを作って入れる（X8）。ダウンロード中の％はフォルダの枠に出す |

## 実装メモ（作業1）

- Supabase：`deck_boxes` 表と `decks.box_id`（migration `20261008090000_add_deck_boxes.sql`）。読めるのはログインした利用者だけ。
- 同期：`04_deck_boxes` を読み、`04_decks.box_id` からデッキの世界観を写す。容量とレベルは箱とデッキの両方で計算する。
- アプリ：デッキ一覧を読むときに箱も一緒に読む（`box:deck_boxes(...)`）。箱に入っていないデッキは、今までどおり1つで並べて1つで入れる。
- 追加：押した時点でフォルダの番号を取っておき、その番号で学習タブの中央に置く。足りないデッキだけを追加し、どのフォルダにも入っていない箱のデッキをまとめてフォルダにする。
- ダウンロード中のフォルダは開けず、長押しメニューに「削除」を出さない。「再試行」は中のデッキをまとめてやり直す。

## 本番へ出す順番

アプリはデッキ一覧と一緒に `deck_boxes` を読むので、**migration を本番に当ててからアプリを出す**。
逆にすると、ギャラリーと学習タブの読み込みが失敗する。

1. migration を本番に当てる（実行前に利用者の承認を得る）— **済み（2026-10-08）**。履歴の番号はファイル名の `20261008090000` にそろえた
2. 原本シートに `04_deck_boxes` のタブを足し、`04_decks` に `box_id` の列を足して、デッキの名前を付け直す（利用者）— **済み**
3. 同期を `--dry-run` で確かめてから流す（実行前に利用者の承認を得る）— **済み（2026-10-08）**。箱2つ・デッキ10個（5個ずつ）・カード1000枚。箱の容量は約55MBと約54MB、レベルはどちらも中
4. アプリを出す

1 と 3 のあいだ（箱がまだ空のとき）は、今までどおりデッキが1つずつ並ぶ。

## 作りの案（作業2：カードの共有）

- `cards` を「主の意味 × 出題形式」で1枚にし、デッキとカードのつながりを別の表（デッキ・カード・並び順）に移す。
- 学習記録（`user_card_progress`）と端末の記録は、カードIDで引くまま変えない。いま A〜J のカードは重ならないので、記録をまとめ直す必要はない見込み。実装の前に本番で確かめる。
- 同期スクリプトとアプリのカード読み込みを、新しい表に合わせる。
