# デッキ追加画面（ギャラリー）の作り直し 要件と引き継ぎ

利用者と合意した要件の正本。まだ要件の途中で、実装は始めていない。
「未決」の項目が全部決まり、要件のすり合わせを終えてから実装に入る。

## この画面の役目

学習タブの空き枠から開き、次に学ぶ公式デッキを1つ選んで学習タブへ入れる。

## メディアの先取り（今の作りとの違い）

今の作り（2026-10-05 時点の origin/main で確認）:

- 文字データ（デッキ・カード・学習記録）は、端末の Application Support に JSON で保存する。SQLite ではない。
- 画像と音声は Supabase Storage の公開バケットから、表示・再生するときに読む。全デッキで同じ。
- 一度読んだ画像は最大 200MB、音声は最大 100MB まで端末のキャッシュに残る。2回目からは通信しない。
- ただしキャッシュは上限を超えると古いものから消え、iOS が空き容量のために消すこともある。
- 一度も見ていない画像・音声は、オフラインでは出ない（[offline-learning-plan.md](offline-learning-plan.md) で「含めない」とした）。

R5b はこの「含めない」を変える。追加のときにデッキの画像・音声をまとめて端末へ入れる。

作業2bへの申し送り：`decks.media_bytes` は「主の意味の例文のうち、デッキの世界観（`decks.concept_id`）に合う
`display_order` 最小の1件の画像と例文音声」＋「標準の単語音声」で数えている。今のアプリ（`WordRecord.toCard`）は
例文を世界観で絞らず、並び順も決めずに先頭を取るので、世界観が2つ以上ある単語では数えたファイルと表示が
ずれうる。先取りで落とすファイルは、この数え方とアプリの表示をそろえてから決める。

## 参考：本当の％でのダウンロード進捗

今の「追加」は、`user_added_decks` に1行書いたあと、追加済みの全デッキのカードと学習記録を
文字データとして読み直す（`AppState.loadOfficialContent`）。画像と音声は学習中にその都度読むので、
追加のときにはダウンロードしていない。

- ％を出すこと自体は、Supabase の使用量を増やさない。
- 「読み終えたデッキの数 ÷ 全体」のおおまかな％なら小さな変更で出せる。ただし、追加済みのデッキが
  少ないうちはほとんど0%から100%へ飛ぶ。
- 通信量（バイト）での正確な％には、通信の受け取り方を作り直す必要がある。しかも文字データは小さいので、一瞬で終わる。
- 使用量を減らしたいなら、追加したデッキの分だけを読む形に変えるほうが効く。
- 画像と音声を先にダウンロードする作り（[offline-learning-plan.md](offline-learning-plan.md)）に
  した場合は、通信量が大きくなる。そのときは％を出す意味も出てくる。
